## Ajouter le paquet

Le paquet est publié à chaque version comme une archive jointe à la publication GitHub (« release ») du dépôt `design`. Dans le `package.json` du projet :

<Code lang="json" code={`{
    "dependencies": {
        "@communeenligne/design": "https://github.com/<organisation>/design/releases/download/v2.2.0/communeenligne-design-2.2.0.tgz"
    }
}`} />

Puis `npm install`. La version est fixée par l'adresse : pour passer à une autre version, changer les deux numéros de l'adresse.

### Pourquoi une archive plutôt que « github:organisation/design#v2.0.0 »

Le paquet se trouve dans le sous-dossier `packages/design` du dépôt. npm sait installer un dépôt Git, mais seulement le `package.json` placé à sa racine : il n'a aucune syntaxe pour un sous-dossier (Yarn et pnpm en ont une, pas npm). L'archive jointe à la publication est produite par `npm pack` dans ce sous-dossier : elle contient exactement les fichiers publiés, s'installe sans Git (les images Docker `node:alpine` n'en ont pas), et ne change jamais une fois publiée.

## Charger les styles

Le paquet est rangé en trois parties, plus le thème Tailwind :

- les **[fondamentaux](/foundations/)** (`foundations/`) : toutes les variables, nommées par rôle (couleurs en clair et en sombre, typographie, espacements, points de rupture, rayons, ombres, mouvement, focus, icônes), et la police Manrope ;
- les **[composants](/components/)** (`components/`) : un fichier par famille, `base.css`, `forms.css`, `navigation.css`, `menu.css`, `content.css`, `landing.css`, `documentation.css` ;
- les **[modèles](/patterns/)** (`patterns/`) : en-tête, pied de page, section, en-tête de page, page de fonctionnalité, page de documentation ;
- `tailwind.css` : le thème Tailwind 4 branché sur les variables (voir [Avec ou sans Tailwind](/getting-started/tailwind/)).

Pour tout le design system (landing, centre d'aide), sans Tailwind, un seul import :

<Code lang="css" code={`@import '@communeenligne/design';`} />

Sans la famille Documentation (bloc de code, exemple, à faire et à éviter, tuiles, page de documentation), pour un projet qui ne montre ni code ni documentation (la landing, le panel) :

<Code lang="css" code={`@import '@communeenligne/design/without-documentation.css';`} />

Ou partie par partie, pour ne prendre que ce qui sert :

<Code lang="css" code={`@import '@communeenligne/design/foundations';           /* variables et police, obligatoires */
@import '@communeenligne/design/components/base.css';   /* une famille de composants */
@import '@communeenligne/design/components/forms.css';
@import '@communeenligne/design/patterns';              /* tous les modèles */
@import '@communeenligne/design/motion.css';            /* animations, facultatif */`} />

Un outil de construction (Vite, Laravel Vite) copie les polices et réécrit leurs adresses. Sans outil, servir le dossier du paquet tel quel : les adresses des polices sont relatives à `fonts/fonts.css`.

## Préparer la page

<Code code={`<!doctype html>
<html lang="fr">
<head>
    <meta charset="utf-8">
    <script src="/design/js/theme-boot.js"></script>   <!-- thème sombre sans clignotement -->
    <script src="/design/js/motion-boot.js"></script>  <!-- animations, facultatif -->
    <link rel="stylesheet" href="/build/app.css">
</head>
<body class="cel-page">
    <a class="cel-skip-link" href="#contenu">Aller au contenu</a>
    …
    <script type="module" src="/build/app.js"></script>
</body>
</html>`} />

- `cel-page` sur `<body>` applique les styles de base : police, couleurs, liens, focus visible. Sans cette classe, rien n'est touché hors des classes `cel-` (le panel Filament garde ses propres styles).
- Les deux scripts d'amorce sont des fichiers à servir depuis le domaine du site (`node_modules/@communeenligne/design/js/`), chargés sans `defer` : aucun script en ligne, donc rien à autoriser dans la politique de sécurité du contenu (CSP).

## Scripts

Neuf modules sans dépendance extérieure, à importer dans le script de la page :

<Code lang="js" code={`import { initTheme } from '@communeenligne/design/js/theme.js'
import { initTabs } from '@communeenligne/design/js/tabs.js'
import { initMenu } from '@communeenligne/design/js/menu.js'
import { initMotion, initSmoothAnchors, initMarquee } from '@communeenligne/design/js/motion.js'
import { initCombobox } from '@communeenligne/design/js/combobox.js'
import { initSearch, indexSearch, endpointSearch } from '@communeenligne/design/js/search.js'
import { initVideo } from '@communeenligne/design/js/video.js'
import { initToc } from '@communeenligne/design/js/toc.js'
import { initFeedback } from '@communeenligne/design/js/feedback.js'

initTheme()            // sélecteur de thème (.cel-theme) ; { cookie: 'cel_theme', storage: false } avec un serveur
initTabs()             // onglets (.cel-tabs)
initMenu()             // menu sur téléphone (.cel-menu)
initMotion()           // apparitions au défilement, entrée des écrans
initSmoothAnchors()    // liens d'ancre data-cel-smooth-anchor
initMarquee()          // bande des références qui défile
initCombobox(element, { search })   // recherche de commune (.cel-combobox)
initSearch(dialog, { search: indexSearch('/search-index.json') })   // palette de recherche (.cel-search)
initVideo()            // vidéo : aperçu et bouton de lecture (.cel-video)
initToc()              // sommaire : la partie lue (.cel-toc)
initFeedback()         // « Cette page vous a-t-elle aidé ? » (.cel-feedback)`} />

Sans script, chaque composant reste utilisable : les onglets s'affichent l'un sous l'autre, le menu sur téléphone est une liste en haut de la page, le sélecteur de thème est fait de liens que le serveur traite, la recherche de commune est un champ texte, la bande des références se fait défiler à la main, le déclencheur de la palette mène à la page de recherche, la vidéo garde les commandes du navigateur, l'avis sur la page est un formulaire.

## Valeurs hors du CSS

`tokens.json`, généré depuis les fondamentaux, donne les valeurs principales sans `var()` : les couleurs en clair et en sombre, les polices et leurs graisses, les points de rupture (en px, des nombres), les espacements, la mise en page, les rayons et les bordures. Pour une valeur demandée hors d'une feuille de style (couleur de la barre du navigateur, courriel, graphique dessiné par un script, `matchMedia`), le projet la lit là au lieu de la recopier.

<Code lang="js" code={`import tokens from '@communeenligne/design/tokens.json' with { type: 'json' }

tokens.colors.primary          // { light: '#1f3a5f', dark: '#…' }
tokens.breakpoints.tablet      // 860
matchMedia(\`(width < \${tokens.breakpoints.tablet}px)\`)`} />

<Code lang="php" code={`// Laravel : la couleur de la barre du navigateur, depuis le paquet installé.
$tokens = json_decode(file_get_contents(base_path('node_modules/@communeenligne/design/tokens.json')), true);
$themeColor = $tokens['colors']['strong']['light'];`} />

## Fichiers du paquet

| Fichier | Contenu |
|---|---|
| `index.css` | Tout : fondamentaux, composants, modèles, animations |
| `without-documentation.css` | Tout sauf la famille Documentation ; `components/without-documentation.css` et `patterns/without-documentation.css` pour Tailwind |
| `tokens.json` | Valeurs principales résolues, couleurs en clair et en sombre |
| `foundations/` | Les variables, un fichier par sujet (`colors.css`, clair sur `:root`, sombre sous `:root.cel-dark` ; `typography.css`, `spacing.css`, `breakpoints.css`, `radius.css`, `shadows.css`, `motion.css`, `focus.css`, `icons.css`) ; `index.css` importe aussi Manrope |
| `components/` | Les composants, un fichier par famille ; `index.css` les importe tous |
| `patterns/` | Les modèles de page ; `index.css` les importe tous |
| `motion.css` | Animations discrètes (apparitions, fondus) |
| `tailwind.css` | Thème Tailwind 4 (bloc `@theme`) branché sur les variables |
| `fonts/` | Manrope 500 à 800, `fonts.css`, licence OFL |
| `icons/` | Icônes SVG, planche `sprite.svg`, `icons.json`, licences |
| `illustrations/` | Illustrations décoratives en `currentColor` (`village.svg`), affichées par `.cel-illustration` |
| `brand/` | Logo et icône de Commune en ligne (hors licence MIT) |
| `js/` | Amorces du thème et des animations, modules `theme.js`, `tabs.js`, `menu.js`, `motion.js`, `combobox.js`, `search.js`, `video.js`, `toc.js`, `feedback.js` |
| `tools/tokens.mjs` | Lecture des variables en Node (tests, documentation) |
